# Rainflow Counting Service

面向道路载荷谱试验的**边收边算**后端：数据块到达一个处理一个，随时可查询
“到目前为止”的雨流循环与累计损伤，显式收尾后给出最终结果。

- 雨流计数：**ASTM E1049**（三点栈式算法）
- 峰谷压缩：同向合并、平台去重、可配滞回门限（计数前滤除小波动）
- 损伤累积：**Palmgren–Miner** 线性累积 + **Basquin** S–N 曲线 `N = C·S^(−m)`
- 平均应力修正：**Goodman**（需要抗拉强度 Su；平均应力为压时不放大）或**不修正**
- 持久化：SQLite（WAL），服务重启后接着追加，不丢数据
- 运行时：Node 20 + TypeScript + Fastify；测试：Vitest

## 快速开始

```bash
npm install
npm test          # 47 个自动化测试
npm run build
npm start         # 监听 0.0.0.0:3000，DB 在 ./data/rainflow.db
```

Docker（镜像基于 `node:20-slim`，SQLite 文件在挂载卷上）：

```bash
docker compose up --build
# 服务在 http://localhost:3000，数据持久化在命名卷 rainflow-data
```

环境变量：`PORT`（默认 3000）、`HOST`、`DB_PATH`（默认 `./data/rainflow.db`）。

## API

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/jobs` | 创建试验作业（材料、S–N、修正方式、门限） |
| `GET` | `/jobs` / `/jobs/:id` | 列出 / 查看作业（含累计损伤） |
| `POST` | `/jobs/:id/blocks` | 按序号追加数据块 `{seq, points}` |
| `GET` | `/jobs/:id/result?offset=&limit=` | 查询截至当前的循环列表与累计损伤 |
| `POST` | `/jobs/:id/finalize` | 显式收尾：残余序列折成半循环计入 |
| `GET` | `/health` | 健康检查 |

### 创建作业

```bash
curl -X POST localhost:3000/jobs -H 'content-type: application/json' -d '{
  "name": "bracket-01",
  "material": "S355",
  "snCurve": {"C": 1.5e12, "m": 3.5},
  "meanStressCorrection": "goodman",   // 或 "none"
  "ultimateStrength": 510,             // goodman 必填
  "hysteresisGate": 0.5                // 可选，默认 0
}'
```

### 追加数据块

```bash
curl -X POST localhost:3000/jobs/$JOB/blocks -H 'content-type: application/json' \
  -d '{"seq": 1, "points": [-2, 1, -3, 5, -1]}'
```

- `seq` 必须从 1 开始逐块递增；跳号或重号（内容不同）返回 **409**。
- 重发**最后一个已应用块**且内容完全一致（SHA-256 校验）视为幂等重试，
  返回 **200** `{"idempotent": true}`，不重复计数。
- `points` 为 1–200000 个有限数值；非数值 / NaN / 空块 / 超限返回 **400** 及明确错误信息。
- 收尾（finalize）后再追加返回 **409**。

### 查询结果

```bash
curl localhost:3000/jobs/$JOB/result
```

```json
{
  "status": "open",
  "cycleCount": 4,          // 循环记录条数
  "totalCount": 2.5,        // 计数之和（全循环计 1，半循环计 0.5）
  "damage": 5.57e-11,       // 累计 Miner 损伤
  "damageOverflow": false,
  "residualLength": 3,      // 尚未闭合的残余峰谷点数
  "cycles": [
    {"index": 0, "range": 3, "amplitude": 1.5, "mean": -0.5, "count": 0.5, "damage": 1.38e-12}
  ]
}
```

**收尾前**的中间查询只统计已确定的循环（残余部分不计入）；**收尾时**残余
序列按标准做法折成半循环追加。已确认的循环列表只增不改——中间结果永远是
最终结果的严格前缀。

### 错误模型

统一返回 `{"error": "...", "code": "..."}`：

- `400` 请求校验失败（缺字段、非法 S–N 参数、Goodman 缺 `ultimateStrength`、
  空块、非数值/NaN、块超过 20 万点、seq 非正整数……）
- `404` 作业不存在
- `409` 序号冲突/跳号（`SEQ_CONFLICT`/`SEQ_GAP`）、作业已收尾（`JOB_FINALIZED`）

## 算法说明

### 峰谷提取（`src/domain/peakvalley.ts`）

流式状态机，把原始时程压成峰谷序列：

1. 同向相邻点合并，只保留当前极值；
2. 平台（等值段）去重为单点；
3. **滞回门限**：反向摆动幅度 `> gate` 才承认一次转向，小于等于门限的小
   波动在计数前直接丢弃（门限为 0 时退化为纯峰谷提取）；
4. 首点必为峰谷点；`flush()`（收尾时）把末尾极值补为最后一个峰谷点，
   尾部低于门限的抖动随之丢弃。

### 雨流内核（`src/domain/rainflow.ts`）

ASTM E1049 三点栈式算法。残余序列存栈，每来一个新峰谷点：记
`X = |最新变程|`、`Y = |前一变程|`——

- `X < Y`：无闭合，入栈；
- `X ≥ Y` 且栈长 = 3：栈首两点构成**半循环**，移除首点（该半循环已确定，
  不随后续数据改变）；
- `X ≥ Y` 且栈长 > 3：中间两点构成**全循环**，移除后继续检查。

收尾时残余序列按相邻对逐一折成半循环。经典示例序列
`-2, 1, -3, 5, -1, 3, -4, 4, -2` 的计数结果（闭循环 E-F + 六个半循环）
与文献表格逐条对上，见 `test/astm.test.ts`、`test/rainflow.test.ts`。

### 损伤计算（`src/domain/damage.ts`）

- 每个循环：`损伤 = count · S_eq^m / C`，其中 `S_eq` 为平均应力修正后的
  幅值（幅值 = 变程/2）。
- Goodman 修正：拉伸平均应力时 `S_eq = Sa / (1 − Sm/Su)`；**压缩或零平均
  应力不放大**。若拉伸 平均应力达到/超过 Su（静强度失效），该循环损伤为
  无穷大，结果中 `damage` 置 `null` 且 `damageOverflow: true`（JSON 无法
  表示 Infinity）。

## 跨块一致性设计（残余状态怎么保）

**选择的方案：持久化增量状态，每块只处理新增部分。**

每处理完一个块，在同一个 SQLite 事务里写入：

- 峰谷过滤器状态（4 个标量：最近峰谷值、方向、当前极值、是否已开始）；
- 雨流内核的残余峰谷序列（JSON 数组）；
- 本块新确认的循环行（只增不改）；
- 逐循环累加的损伤与计数。

**为什么这样一定一致**：整条流水线是“点流 → 峰谷 → 雨流 → 损伤”的确定性
折叠（fold），全部状态都在事务里随块落库。处理第 k 块 = 用第 k−1 块落库
的状态继续折叠，与把整条时程一次喂入在数学上是同一个折叠，因此**逐点、
随机切块、一整块，循环列表与损伤逐位一致**（测试用严格相等断言，含浮点
损伤——损伤按循环确认顺序逐个累加，求和顺序与分块无关）。块边界落在峰值
上、单点块、全常数块都只是状态机的普通输入，无需特判。

**被否决的方案：每次追加都重放全部历史。** 它不需要存任何状态，实现最
“笨”也最显然一致，但每块重算代价是 O(已收总量)，整段试验累计 O(n²)。
应变片一跑几十小时、每几分钟一块的场景下，后期每块都要重算几个小时的数据，
违背“边收边算、随时可查”的目标。

**所选方案的代价**：

- 每块多一次状态读写：峰谷状态恒定 4 个标量；残余序列是 JSON 数组，道路
  载荷数据下通常只有几十个点（病态的单调递减变程输入才会让它增长）。
- 存储：每个循环一行（幅值/均值/计数/损伤），10⁶ 个循环约几十 MB，
  查询分页（`offset`/`limit`）。
- 实现上要保证状态读写与循环插入同事务，否则崩溃后状态与循环日志会错位
  ——由 SQLite 事务保证。

## 持久化与重启

- SQLite WAL 模式；每个块（状态更新 + 循环插入 + 累计值）一个事务，崩溃
  只会回滚未提交的块，已提交的块重启后原样可见。
- 作业配置、状态、循环、累计值全部落库；服务重启后可直接继续追加
  （`test/restart.test.ts` 覆盖：追加到一半关掉服务、换实例接着追加，
  结果与不中断逐位一致；重启后重发最后一块仍按幂等处理）。

## 测试覆盖（`npm test`）

- **分块不变性**：同一序列按逐点 / 随机切块 / 两块 / 一整块喂入（含门限
  开启），收尾后循环列表与损伤完全一致（严格相等）。
- **中间查询语义**：残余不计入、收尾折半循环、中间结果是最终结果的前缀。
- **ASTM E1049 经典示例**：与文献表格逐条对上（单块与分块两种喂法）。
- **变换性质**：时程 ×2 → 幅值/均值 ×2、损伤 ×2^m；+常数 → 均值平移、
  损伤不变；取负 → 幅值不变、均值取负。
- **序号与幂等**：跳号/重号 409，同序号同内容幂等；收尾后追加 409；
  收尾本身幂等。
- **重启**：追加到一半重启，结果与不中断一致；重启后幂等重放仍成立。
- **输入校验**：非数值、NaN、空块、200001 点、非法 seq、非法作业配置、
  Goodman 缺 Su，均为明确 400。
- **Goodman**：拉伸平均放大、压缩平均不放大（与不做修正的结果一致）。
